v1.1.3.26 (build 92) — IPSec traffic counter on profile→profile switch (+ health).

build 91's fix didn't trigger on an IPSec→IPSec switch because that path reuses
the same network interface AND doesn't reset the counter's tracking, so it stayed
pinned to the previous session and clamped to 0. It now re-identifies + re-baselines
whenever a NEW IKE session starts (detected via the connection's connected-date),
independent of how the switch was triggered.

Knock-on: the tunnel-health pill treats live traffic as a "healthy" signal, so a
stuck-at-0 counter could make it falsely show degraded/recovering. With the counter
fixed, health reflects reality again.

HOW TO TEST
- Connect IPSec profile A → counter climbs, health = healthy.
- Switch DIRECTLY to IPSec profile B → counter climbs (not 0), health stays healthy.
- WireGuard ↔ IPSec still fine.

REGRESSION CHECK
- Single active VPN, WG/AWG/OVPN counters + health, pools, delete cleanup.
