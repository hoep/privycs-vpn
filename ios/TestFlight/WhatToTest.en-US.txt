v1.1.3.11 (build 82) — IPSec (IKEv2) certificate handling.

Targets the IPSec connection that connected as a "Personal VPN" and then
flapped (reconnected over and over). This build reworks the client certificate
handling for IPSec.

WHAT CHANGED
- The client certificate (PKCS#12) is now imported into the keychain and
  referenced properly (identityReference) instead of passed inline — the inline
  path is unreliable for IKEv2 and was a likely cause of the failed
  connect/flap.
- The CA chain from the profile is imported too.
- Gateway IPSec configs are now named "gw-ipsec-<id>" (like Android) instead of
  a random id, so re-downloading updates in place instead of duplicating.

HOW TO TEST
1. Remove any old IPSec config, then pull a fresh IPSec config from the gateway.
2. Connect. Watch whether it establishes and STAYS up (no endless flapping).
3. Connect/disconnect a few times.

IMPORTANT — if it STILL flaps, please grab a device log of one attempt
(Settings reachable, or Console): the IKE/IKE_AUTH error code tells us whether
the remaining blocker is SERVER certificate trust. iOS (unlike Android's
strongSwan) validates the gateway's server certificate against the system trust
store, and an app cannot install a trusted root for a self-signed gateway CA —
that part would need a publicly-trusted server certificate on the gateway. The
log will confirm which it is.

NOTE: WireGuard / AmneziaWG / OpenVPN are unaffected by this change.
