v1.1.3.9 (build 80) — Same-protocol-first failover.

This build fixes how automatic failover chooses the next server when a
connection has MULTIPLE configs of the same protocol (e.g. two WireGuard
endpoints) inside one connection.

WHAT CHANGED
- When the active config fails, failover now tries the OTHER configs of the
  SAME protocol first (a second WireGuard endpoint, etc.) BEFORE switching to a
  different protocol. Previously it could jump to another protocol before
  exhausting the same-protocol alternates.

HOW TO TEST
1. Create ONE connection that holds several configs, including two of the same
   protocol — e.g. WireGuard-ServerA + WireGuard-ServerB + an OpenVPN config.
2. Connect, then make the active endpoint fail (e.g. ServerA unreachable / wrong
   port, or pull it mid-session so the health monitor recovers).
3. Confirm it fails over to the OTHER WireGuard endpoint (ServerB) FIRST, and
   only moves to OpenVPN if BOTH WireGuard endpoints fail.
4. Check the failover toast/notification names the server it landed on.

REGRESSION CHECK (should be unchanged)
- Normal connect/disconnect over WireGuard, AmneziaWG, OpenVPN, IPSec.
- Single-config connections and pools behave exactly as before.
- Manual protocol pill switch still works.
