v1.1.5.3 (build 99) — widget protocol switch fixed.

The widget log revealed it: the keychain read works now, but the SWITCH failed
with "configuration type is wrong" — because the connection was running as the
IPSec personal VPN, and starting a packet-tunnel (WireGuard) while IPSec is
active is rejected. The widget now deactivates the active IPSec slot (and any
other tunnel) first, then starts the chosen protocol — the same single-active-VPN
step the app does.

HOW TO TEST
- Connect a connection that has both IPSec and WireGuard (e.g. "Privycs Shielded").
- From the widget, tap the WireGuard pill → it should switch to WireGuard (and
  vice-versa). The active protocol on the widget + in Settings ▸ VPN should match.
- If it STILL doesn't switch: open the app → Settings → Logs and send the
  "widget switch[" lines (they now also show the deactivation + start result).

REGRESSION CHECK
- IPSec VPN-IP shows only the private address (no public v6); OpenVPN counter +
  info; WG/AWG; double-tap guard; pools.
